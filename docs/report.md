## Executive Summary

I built the Flashcard Quizzer, a Python command-line app that loads flashcard decks from JSON and quizzes the user in sequential, random or adaptive order. It validates decks with precise error messages, gives colored feedback, prints a summary table, remembers which cards each user misses and uses that history to ask the hardest cards first.

The code was generated by Claude Code from a phased brief I wrote around the project rubric. After every phase the agent reviewed its output against the course checklist, ran the tests and linters, logged the interaction and stopped for my approval. More than ten defects were caught along the way, by tests, by running the real program on Windows, by mypy and by review. All are documented in `docs/ai_edit_log.md`.

## Project Overview

### Problem Statement
Flashcards work best when you practise what you do not know yet, but simple quiz tools repeat every card in the same order. I wanted a lightweight terminal tool that reads plain JSON decks and keeps bringing back the cards I get wrong.

### Solution Approach
- **Layers:** data (`models.py`, `utils/file_handler.py`, `data_loader.py`) → logic (`quiz_engine.py`) → presentation (`ui.py`, `main.py`).
- **Patterns:** Strategy for the quiz modes, Factory to create them from `--mode`.
- **Testability:** the engine never prints; it receives an input function and an output object.
- **Stack:** Python 3.10 standard library plus `colorama` for Windows colors; pytest, black, isort, flake8, mypy and bandit for quality.

### Final Features
- [x] Array and object JSON formats, with validation that names the bad card
- [x] Sequential, random (`--seed`) and adaptive modes
- [x] Adaptive re-queue of missed cards plus cross-session miss history
- [x] Colored feedback, summary table and `--no-color`
- [x] `--stats`, `--limit N` and `--export-missed`
- [x] Clean exit on "exit", Ctrl+C or EOF, with no traceback
- [x] Logging to a file

### Most Valuable AI Interactions

#### Example 1: Pushing back on my own specification
**Context:** Building the deck loader.  
**AI Prompt:** "`utils/file_handler.py` ... turns ... errors into `FlashcardLoadError`."  
**AI Response:** It noticed that this makes a utility import from the application layer.  
**Your Changes:** I accepted a `JSONFileError` in `utils/` that `data_loader` converts to `FlashcardLoadError`.  
**Outcome:** `utils/` stays reusable and no circular import can appear.

#### Example 2: Running the real program found four bugs
**Context:** Phase 3, the CLI.  
**AI Prompt:** "Must work: `python main.py --mode sequential --file data/glossary.json` ..."  
**AI Response:** Code that passed all 74 unit tests and every linter.  
**Your Changes:** Piped games showed a garbled em dash, an error printed twice, a 170-character stats table and an export that could overwrite the deck. All four were fixed.  
**Outcome:** I now treat "tests pass" as necessary, not sufficient.

#### Example 3: Evaluating a security warning
**Context:** Phase 5 quality gate.  
**AI Prompt:** "Run, and fix until all are clean."  
**AI Response:** bandit flagged `random.Random(seed)` as insecure.  
**Your Changes:** A cryptographic generator cannot be seeded and would break `--seed`, so that one line was suppressed with a written reason.  
**Outcome:** Clean scan without losing a feature.

## Software Engineering Practices

### Code Quality Measures
- [x] Code formatting (Black, isort)
- [x] Linting (flake8, mypy; plus bandit)
- [x] Type hints on every function, checked with `disallow_untyped_defs`
- [x] Documentation/comments (docstrings everywhere)
- [x] Error handling (custom exceptions, no bare `except`)

### Testing Strategy
- **Types of tests:** unit tests per module, integration tests that call `main(argv)`, and one real subprocess test.
- **Fixtures:** `fake_input` scripts answers or raises `KeyboardInterrupt`/`EOFError`, and `isolated_home` keeps tests away from my real history.
- **Coverage:** 150 tests, 100% statement coverage.
- **Approach:** not strict TDD, but every required test name was fixed in the prompt before the code existed.

### Design Patterns Used
- **Strategy:** `QuizMode` with `SequentialMode`, `RandomMode` and `AdaptiveMode`. The modes differ only in which card comes next, so each is a swappable algorithm and `QuizSession` never checks which one it has.
- **Factory:** `QuizModeFactory` maps `--mode` names to classes through a registry. Adding "Spaced Repetition" means one new class plus one dictionary line.
- **Rejected:** an Observer for statistics. `main` updates history from `SessionStats`, so the class would have had no real job.

### Code Structure and Organization
Each module has one responsibility, and only `ui.py` prints. A refactor during review made `RandomMode` reuse `SequentialMode` instead of duplicating its methods.

## Technical Challenges and Solutions

### Challenge 1: Guaranteeing adaptive mode ends
**Problem:** Re-queuing missed cards could loop forever.  
**Solution:** A per-card repeat counter (maximum 3) and insertion two positions later.  
**AI Involvement:** The AI designed it; `test_adaptive_max_repeats_ends_quiz` proves termination.  
**Lessons Learned:** Write the termination guarantee as a test.

### Challenge 2: Garbled output on Windows
**Problem:** Piped output used cp1252, so "—" appeared as "�".  
**Solution:** Non-terminal streams are switched to UTF-8 at startup.  
**AI Involvement:** Found only by running real games.  
**Lessons Learned:** Test on the actual target platform.
